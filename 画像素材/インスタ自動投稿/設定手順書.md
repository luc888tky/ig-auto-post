# Instagram自動投稿 設定手順書

結論：下の①〜⑦をやれば、10/21以降は毎日20:00（日本時間）にPCなしで自動投稿されます。所要時間は約30〜40分、費用は0円です。

仕組み：GitHub（無料）が毎日20:00に `post_instagram.py` を動かし、Instagram公式APIでカルーセル（5枚）を投稿します。10/20までの投稿は今のMeta Business Suiteの予約が担当し、この仕組みは10/21から引き継ぎます（重複しません）。

> 画面の文言は変わることがあります。違う表示が出たら、その画面のスクリーンショットを私に送ってください。

## あなたがやること

### ① GitHubのアカウントを作る（無料）
https://github.com → Sign up。メールアドレスで作成します。

### ② 公開リポジトリを作る
右上の「＋」→ New repository
- Repository name：`ig-auto-post`（好きな名前でOK）
- **Public** を選ぶ（Instagramが画像を取りに来るため、公開が必要です。中身は宣伝用の画像と文章だけです）
- 「Add a README file」はチェックしない → Create repository

### ③ ファイルをアップロードする
作ったリポジトリの画面で「uploading an existing file」をクリック。
「インスタ自動投稿」フォルダの中から、次の4つを画面にドラッグします。
- `images` フォルダ（中に画像が d30_1.jpg のような名前で入っています）
- `posts.json`
- `posted.json`
- `post_instagram.py`

（`.github` フォルダは次の④で作るので、ドラッグしなくて大丈夫です）
下の「Commit changes」を押します。

### ④ 自動実行の設定ファイルを作る
リポジトリの画面で Add file → **Create new file**
- 上のファイル名欄に `.github/workflows/post.yml` と入力（スラッシュを打つとフォルダに切り替わります）
- 本文には、フォルダ内の `.github/workflows/post.yml` の中身を全部コピーして貼り付け（下にも同じ内容があります）
- Commit changes

```yaml
name: Instagram自動投稿

on:
  schedule:
    - cron: "0 11 * * *"   # 毎日 日本時間の20:00（UTC 11:00）
  workflow_dispatch:
    inputs:
      date:
        description: "投稿する日付（YYYY-MM-DD）。空なら今日"
        required: false
      dry_run:
        description: "true なら投稿せず確認だけ"
        required: false
        default: "false"

permissions:
  contents: write

concurrency:
  group: instagram-post
  cancel-in-progress: false

jobs:
  post:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: 投稿する
        env:
          IG_TOKEN: ${{ secrets.IG_TOKEN }}
          NEW_TOKEN_FILE: ${{ runner.temp }}/new_token.txt
          INPUT_DATE: ${{ github.event.inputs.date }}
          DRY: ${{ github.event.inputs.dry_run }}
        run: |
          ARGS=""
          if [ -n "$INPUT_DATE" ]; then ARGS="$ARGS --date $INPUT_DATE"; fi
          if [ "$DRY" = "true" ]; then ARGS="$ARGS --dry-run"; fi
          CHECK_URLS=1 python3 post_instagram.py $ARGS

      - name: 投稿済みの記録を保存
        if: always()
        run: |
          if [ -n "$(git status --porcelain posted.json)" ]; then
            git config user.name "github-actions"
            git config user.email "github-actions@users.noreply.github.com"
            git add posted.json
            git commit -m "投稿済みを記録"
            git push
          fi

      - name: トークンが更新されていたらSecretsを更新（GH_PATを設定した場合のみ）
        if: always()
        env:
          GH_TOKEN: ${{ secrets.GH_PAT }}
          NEW_TOKEN_FILE: ${{ runner.temp }}/new_token.txt
        run: |
          if [ -n "$GH_TOKEN" ] && [ -f "$NEW_TOKEN_FILE" ]; then
            gh secret set IG_TOKEN --repo "$GITHUB_REPOSITORY" < "$NEW_TOKEN_FILE"
            echo "IG_TOKEN を更新しました"
          fi
```

### ⑤ Meta for Developersでアプリを作り、トークンを発行する
1. https://developers.facebook.com に、Instagram運用用のFacebookアカウントでログイン → 開発者として登録
2. 「アプリを作成」→ ユースケースは **Instagramでコンテンツを管理する**（Business系）を選ぶ → アプリ名は自由
3. アプリの画面で **Instagram API（Instagramログインを使うほう）** を開く
4. 権限に `instagram_business_basic` と `instagram_business_content_publish` を含める
5. 投稿するInstagramアカウント（tky89260308）を、アプリの「Instagramテスター」に追加
6. Instagramアプリ側で招待を承認（設定 → ウェブサイトのアクセス許可 など。表示は環境で違います）
7. アプリ画面の「アクセストークンを生成」→ Instagramでログインして許可 → 表示された**長い文字列（トークン）をコピー**

トークンは「パスワードと同じ」です。他の人やチャットには貼らないでください（私にも送らないでください）。

### ⑥ トークンをGitHubに保存する
リポジトリの Settings → Secrets and variables → Actions → **New repository secret**
- Name：`IG_TOKEN`
- Secret：⑤でコピーしたトークン
- Add secret

### ⑦ 動作テスト（投稿はしない確認）
リポジトリの Actions タブ → 「Instagram自動投稿」→ Run workflow
- date：`2026-10-21`
- dry_run：`true`
緑のチェックが付き、ログに画像5枚の確認とキャプションが表示されればOKです。

## 運用メモ

- **トークンの期限**：最初は約60日有効です。投稿のたびに延長を試みますが、更新後の値の保存には追加設定（GH_PAT）が必要です。設定しない場合は、**約50日ごと（目安：11月中旬）にトークンを作り直して `IG_TOKEN` を差し替えてください**。期限が切れると投稿が失敗し、GitHubから失敗メールが届きます。
- **投稿時刻**：GitHubの仕様で、20:00から数分〜数十分遅れることがあります。
- **投稿の追加**：`posts.json` に日付・画像・キャプションを足すと、その日に投稿されます。追加分の素材は私が作ります。
- **投稿を止めたいとき**：Actionsタブ → 「Instagram自動投稿」→ 右上「…」→ Disable workflow。
- **二重投稿の防止**：投稿済みの日付は `posted.json` に記録され、同じ日は再投稿されません。
- **審査について**：自分のアカウントだけに使う場合、アプリの審査（App Review）は通常不要ですが、公式ドキュメントには明記がありませんでした。権限エラーが出たら教えてください。
